# 설계 결격 신호

합성 전에 모든 후보를 거른다. 결격 신호 하나는 그 모양을 고치거나 버릴 이유다.

## Shallow module (얕은 모듈)

얕은 모듈은 큰 인터페이스를 드러내면서 숨기는 복잡도는 적다. 깊이는 공개 면의 크기에 비해 그 뒤에 숨긴 기능과 정책이 얼마나 많은지로 판단한다. 작은 인터페이스 뒤에 실질적인 동작이 있는 쪽을 고른다.

깊은 모듈과 깊은 호출 사슬을 헷갈리지 않는다. 깊은 호출 사슬은 이해를 여러 계층에 흩는다. 깊은 모듈은 기능을 인터페이스 하나 뒤에 모은다.

신호:

- 호출자가 한 작업을 끝내려고 메서드 여러 개를 맞춰 불러야 한다.
- 공개 옵션이 내부 단계나 구현 선택을 드러낸다.
- 인터페이스를 배워도 구현을 배워야 하는 수고가 줄지 않는다.

## Information leakage (정보 새기)

정보가 새면 여러 모듈이 같은 내부 결정에 기댄다. 표현, 정책, 프로토콜 세부가 두 곳 이상에 나타나서, 그것을 바꾸려면 여러 곳을 함께 고쳐야 한다.

전송·wire 타입을 공개로 다시 내보내는 것도 새는 것이다. 외부 데이터는 인터페이스 뒤에서 도메인 타입으로 파싱한다. 저장 스키마, 프레임워크 객체, 프로토콜 세부는 비공개로 둔다.

## Temporal decomposition (시간순 분해)

시간순 분해는 모듈을 그것이 가진 지식이 아니라 실행 순서로 나눈다. load, validate, transform, save 단계를 따로 두면 표현 하나와 그 불변식이 여러 경계에 되풀이되기 쉽다.

코드를 도메인 지식과 소유권으로 묶는다. 서로 다른 시점에 도는 메서드라도 같은 결정을 지키면 한 모듈에 둔다.

## Pass-through method (그냥 넘기는 메서드)

그냥 넘기는 메서드는 같은 인자를 같은 모양의 다른 메서드에 넘긴다. 복잡도를 숨기지 않고 계층만 더한다.

지우거나, 작업을 끝낼 수 있는 모듈로 책임을 옮긴다. 넘기는 경계가 정책, 변환, 별개의 추상화를 더할 때만 남긴다.

## Split ownership (쪼개진 소유)

같은 상태를 모듈 둘 이상이 쓰거나 저마다 사본을 가진다. 한 쪽을 고치는 에이전트는 다른 쓰는 쪽을 보지 못해 규칙이 갈라진다.

상태마다 주인을 하나로 둔다. 다른 모듈은 읽기만 하거나 주인에게 바꿔 달라고 한다.

## Two ways to do one task (한 일에 두 길)

같은 일을 하는 방법이 둘 이상이다. 에이전트는 먼저 찾은 길을 베끼므로 모든 길이 계속 호출자를 늘린다.

길을 하나만 둔다. 다른 길의 호출자를 옮기고 같은 변경에서 그 길을 지운다.

## Importable internals (가져다 쓸 수 있는 내부)

호출자가 모듈 내부를 import 할 수 있다. 에이전트는 컴파일되는 가장 짧은 길을 택하므로 내부를 직접 가져다 쓰고, 그러면 내부가 인터페이스가 된다.

밖에서 내부에 닿을 수 없게 해서 밖에서의 import 가 빌드를 깨게 만든다.

## Hand-synced list (손으로 맞추는 목록)

같은 항목을 두 곳 이상이 나열하고, 항목을 더하려면 모든 목록을 고쳐야 한다. 목록 하나만 본 에이전트는 그것만 고친다.

목록을 하나만 두고 나머지는 거기서 끌어낸다. 끌어낼 수 없으면 목록이 서로 다를 때 빌드가 실패하게 만든다.
