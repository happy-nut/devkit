# 시각 동등성

**언제.** UI 를 픽셀 단위로 같게 만든다. 두 구현 맞추기, 스타일 시스템 이전.

**소유.** 픽셀 단위 동등성을 소유한다. 기준선이 명세다. 기준선은 건드리지 않는다. 동등성은 눈이 아니라 이미지 diff 로 검증한다.

## 단계

1. 이전을 시작하기 전에 기준선부터 만든다.
   지금 컴포넌트를 상태별로 스크린샷하는 시각 회귀 하네스(playwright 스크린샷 등)를 만들고, 두 구현을 맞추는 일이면 목표 쪽도 찍는다. 기준선이 없으면 동등하다고 말하지 않는다. 후속이 아니라 먼저 막는 선행 조건이다.
2. 지름길 금지 조항을 적고 지킨다.
   하네스 수정 금지, 기준선 조작 금지, diff 를 통과시키려는 컴포넌트 재구성 금지. 기준선이 이상해 보이면 멈추고 AskUserQuestion 으로 묻는다. 고치지 않는다.
3. 한 번에 컴포넌트 하나씩 옮긴다.
   컴포넌트마다 owner 하나를 두고 `isolation: "worktree"` 로 병렬로 돌린다(principles.md 의 Separate Before Serializing Shared State). 공유 프리미티브는 먼저 막는 단계로 가장 먼저 옮긴다.
4. 컴포넌트마다 같은 표면에서 기준선과 이미지 diff 로 검증한다.
   브라우저 도구로 찍고 픽셀 diff(`pixelmatch`, ImageMagick `compare -metric AE` 등)로 비교한다. diff 가 0 이 아니면 실패다. 픽셀 차이를 조사한다. 컴포넌트마다 diff 가 0 이 될 때까지 Claude Code `/loop` 스킬로 돈다.
5. 컴포넌트마다, 또는 안전한 묶음마다 `opening-a-pr.md` 로 PR 을 연다.

## 답변에 넣을 것

- 옮긴 컴포넌트와 각각의 diff 결과.
- 기준선 하네스 위치.
- 남은 것.
