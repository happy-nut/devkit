# 힐클라임

**언제.** 측정할 수 있는 지표 하나를 목표까지 꾸준히, 과학적으로 끌어올린다. 한 번 고치는 일은 `bug-fix.md` 나 `perf-issue.md` 다. 이것은 루프다.

**소유.** 지표와 실험의 정직함을 소유한다. 감독하고 리뷰한다. 시도는 서브에이전트에 맡긴다.

핵심 규율은 「변경 하나, 측정 하나, 채택 아니면 되돌림」이다. 검증하지 않은 변경을 쌓지 않는다. 코드를 읽고 이겼다고 하지 않는다(principles.md 의 Prove It Works).

## 단계

1. 지표를 고르기 전에 워크로드와 구조를 파악하고 정지 조건을 정한다.
   대상을 추적하고, 결과를 움직일 수 있는 현실적 차원(데이터 크기, 이력, 상태, 동시성)을 이름 짓고, 사용자의 불만을 재현하는 케이스를 고른다. 재현하는 케이스가 없으면 힐클라임 말고 재현부터 고친다. 그다음 지표 하나, 좋아지는 방향, 확인 가능한 정지 조건을 정한다. 정지 조건은 목표와 최소 시도 횟수를 짝지어 운 좋은 초반 승리로 끝나지 않게 한다. 「기준선보다 50% 이상 좋아지고 10회 이상 반복」이 이 모양이다. 사용자가 숫자를 주면 그 숫자를 쓰고, 아니면 가장 나은 값을 정해 이유와 함께 보고한다.
2. 측정 하네스를 만들고, 민감도를 증명하고, 동결한다(principles.md 의 Build the Lever).
   대비되는 현실 워크로드를 돌려 목표 케이스가 증상을 재현하고 쉬운 케이스와 예상대로 갈리는지 확인한다. 하네스가 둘을 구분하지 못하면 워크로드나 지표를 고친다. 동결 전에 `/devkit:bench` 로 하네스를 검토하고, 하네스가 오류 수와 처리한 일의 양을 찍게 한다. 동결 뒤에는 명령 하나가 잡음을 넘을 만큼 표본을 뽑아 지표를 낸다(한 번 실행이 아니라 N 회 중앙값). 어떤 변경보다 먼저 기준선 지표와 회귀 관문(계속 통과해야 할 테스트)의 초록 실행을 기록한다.
3. `/devkit:log` 로 결정 기록을 연다.
   `decision.tsv` 에 시도마다 한 줄. 열은 id, hypothesis, change, before, after, delta, tests, verdict(kept 또는 reverted), note. 매 시도 전에 읽는다. 저장소 트리 밖에 둔다(gitignore).
4. 가설마다 1단계의 구조 모델에 근거해 구체 메커니즘을 이름 짓는다.
   「첫 그리기를 막으니 X 를 부팅 경로 밖으로 미룬다」처럼 쓴다. 「뭔가 메모이즈해 본다」는 가설이 아니다. 성능 지표면 `perf-issue.md` 2단계의 성능 주문 순서로 가설을 줄 세운다. 순서만 빌리고 그 단계의 정지 규칙은 빌리지 않는다.
5. 회차마다 가설 하나로 돈다.
   - 범위를 좁게 정해 서브에이전트(`subagent_type: "devkit:worker"`, 모델 `opus`, 가장 어려운 변경이면 `fable`)에 맡긴다. 직접 치지 말고 감독하고 diff 를 리뷰한다(principles.md 의 Guard the Context Window). 독립 가설이 여럿 살아 있으면 서브에이전트마다 `isolation: "worktree"` 로 병렬로 보낸다(principles.md 의 Separate Before Serializing Shared State).
   - 동결한 하네스로 전후를 재고, 회귀 관문을 돌린다.
   - 지표가 잡음을 넘어 움직이고 관문이 초록일 때만 채택한다. 아니면 변경을 전부 되돌린다. 「도움이 될지도」 싶은 손질은 남기지 않는다.
   - 채택마다 커밋 하나. 바꾼 파일만 스테이징한다(`git add <files>`, `-A` 금지). 채택이든 되돌림이든 기록 한 줄을 남긴다.

   회차마다 다음 회차 전에 검사로 끝낸다(principles.md 의 Sequence Work into Verifiable Units). 사람 없이 돌면 `autonomous-run.md` 의 깨우기 장치만 빌린다. 정지 규칙은 빌리지 않는다.
6. 첫 정체를 넘는다.
   연속 거절로 멈추면 범주를 바꾸거나, 아깝게 진 것들을 묶거나, 소스를 다시 읽거나, 더 과감한 시도를 한 뒤에 다 올랐다고 결론짓는다. 정확성과 단순성이 숫자보다 앞선다. 동작을 깨는 승리는 되돌리고, 숫자를 지키는 단순화는 남긴다(principles.md 의 Laziness Protocol).
7. 정지 조건을 채우거나, 남은 아이디어가 비용만큼 값하지 않을 때 멈춘다.
   조건을 채우려고 조건을 느슨하게 하지 않는다. 시도 안 한 값싼 가설이 남았으면 그만두지 않는다. 막히면 헛돌지 말고 보고한다.
8. 채택한 커밋을 들어간 순서대로 쌓아 `opening-a-pr.md` 로 PR 을 연다.

## 답변에 넣을 것

- 지표와 목표, 기준선에서 최종까지와 그 퍼센트 차이.
- 돈 회차 수(채택 대 되돌림).
- 채택한 수정 하나에 한 줄씩.
- `decision.tsv` 경로.
- 더 간다면 다음에 해 볼 가장 좋은 아이디어.
