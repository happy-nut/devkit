# 런타임 포렌식

**언제.** 살아 있는 프로세스의 증상(누수, 입력 없이 CPU 를 먹는 회전, 화면 글리치)을 실시간 계측으로 진단한다.

**소유.** 진단을 소유한다. 소스로 이론을 세우지 말고 살아 있는 프로세스를 계측한다. 산출물은 근거를 단 진단이다. 수정이 아니다.

## 단계

1. 같은 표면에서 실제 신호를 잡는다.
   회전하는 프로세스는 CPU 프로파일, 누수는 힙 스냅샷, 화면 글리치는 CDP trace. 웹은 브라우저 도구(playwright 로 CDP 접근), Node 는 `node --inspect` 에 CDP 로 붙고, 그 밖의 프로세스는 터미널의 프로파일러(`py-spy dump`, `sample` 등)를 쓴다. 짐작이 아니라 실제 산출물이어야 한다.
2. 산출물을 결정적 증거로 줄인다.
   뜨거운 경로의 함수, 새는 객체에서 GC 루트까지의 보유 사슬, 입력 없이 도는 루프. 큰 산출물은 서브에이전트에서 파싱하고 줄인 결과만 본 스레드에 둔다(principles.md 의 Guard the Context Window). 파싱은 `sonnet` 서브에이전트로 충분하다.
3. 믿기 전에 메커니즘을 증명한다.
   돌고 있는 프로세스에 CDP eval(브라우저면 페이지 JavaScript 실행 도구)로 계측을 넣거나, 리로드 없이 라이브 코드를 고쳐 가설을 싸게 확인한다. 측정은 수 초짜리로 끝낸다. 운영 중인 프로세스를 오래 멈추게 하는 무거운 계측은 넣지 않는다.
4. 결과를 소스로 매핑한다.
   파일, 심볼, 할당하거나 예약하는 줄.
5. 처리량 점검은 한 줄로 둔다.
   `처리량 점검: n/a, 읽기 전용 포렌식`

## 답변에 넣을 것

- 잡은 신호, 줄인 결과, 메커니즘을 증명한 방법, 소스 위치, 산출물 경로.
- 요청이 없으면 수정하지 않는다. 원인이 나오면 `bug-fix.md` 나 `perf-issue.md` 로 넘긴다.
